# CMS: узгоджене бачення та план переходу

- [Повторне використання BW CMS](CMS_REUSE_REVIEW.md): актуальна карта коду, прив’язки до ALM, рекомендації для інтеграції, пакетів та оновлень (29.10.2026).

Ці документи описують цільову CMS для Astro-сайтів. Вони є планом розвитку, а не описом повністю готової системи.

- [Архітектура](CMS_ARCHITECTURE.md): принципи, сховище, чернетки, публікація, межі системи.
- [Автоматична надбудова над Astro](CMS_CODE_FIRST_ARCHITECTURE.md): виявлення секцій і простого контенту з коду, параметри компонентів, конфлікти та план реалізації.
- [Модель контенту](CMS_CONTENT_MODEL.md): типи записів, схеми й контракт із компонентами Astro.
- [Інтерфейс](CMS_UI_UX_SPEC.md): щоденна робота редактора.
- [План переходу](CMS_ROADMAP_EXPANSION.md): послідовність робіт від поточного ALM до універсальної CMS.
- [Критерії готовності](CMS_ACCEPTANCE.md): перевірні сценарії кінцевого результату.
- [Поточний стан](CMS_IMPLEMENTATION_STATUS.md): що вже працює локально й що залишається зробити.
- [Медіатека та налаштування сторінок](CMS_MEDIA_AND_PAGE_SETTINGS.md): поточна поведінка, межі й правила публікації.
- [Єдиний стандарт контенту](CMS_CONTENT_STANDARD.md): записи сторінок, стабільні ключі та підключення іншого Astro-проєкту.
- [Підготовка Astro-сайту](CMS_SITE_PREPARATION.md): які дані зробити спільними Const, як підключити змінні та перевірити їх використання.

**Узгоджена ціль:** готова до повторного використання CMS для сторінок, статей, портфоліо, медіа та маркетингового контенту. Перший спосіб зберігання — файли в Git без окремої бази даних. Агент може швидко підключати CMS до іншого Astro-сайту й керувати контентом через контрольовані операції.

**Поза поточним переходом:** магазин, бронювання та візуальне складання сторінок із перестановкою секцій. Схеми та ID мають залишити шлях до такого конструктора в наступному етапі.

**Поточний пріоритет:** спершу переносимо статичний контент ALM і його адмінку на нове ядро, потім налаштовуємо віддалену публікацію. До статей і портфоліо повернемося згодом; їхній локальний прототип зберігаємо.

- [CMS fields architecture](CMS_FIELD_ARCHITECTURE.md): supported field types, defaults, storage and agent integration.
