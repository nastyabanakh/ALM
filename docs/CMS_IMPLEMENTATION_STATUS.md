# Поточний стан реалізації

Цей файл описує виконане й незавершене без підміни цільових критеріїв. Готовність визначає [CMS_ACCEPTANCE.md](CMS_ACCEPTANCE.md).

## Уже працює локально

- `npm run dev:cms` запускає Astro та локальний API на `127.0.0.1:3001`; тестові запити не пишуть у GitHub.
- Немає робочих значень пароля й ключа сесії за замовчуванням. Локальний `.env.local` ігнорується Git.
- `/admin` працює через локальний API. Неавторизоване читання контенту відхиляється. Поля головної, SEO, локальної команди та зобов’язань зберігаються як серверна чернетка нового ядра й публікуються локально в один запис `pages`.
- Нова сторінка `/cms` показує форми статей і портфоліо з одного опису полів. Є локальні серверні чернетки, перевірка версії чернетки, валідація перед локальною публікацією та окремі файли записів.
- Є захищене локальне прев'ю чернетки статті/проєкту. Це прототип окремого шаблону; перед завершенням переходу прев'ю треба зробити візуально тотожним реальним Astro-сторінкам.
- Media читає файлові папки `public/assets`, дозволяє завантажувати PNG/JPEG/WebP/MP4, створювати папки, змінювати редакторську назву й спільний alt та замінювати файл за тією самою адресою. Для Replace створюється локальна резервна копія. Деталі й межі описано в [CMS_MEDIA_AND_PAGE_SETTINGS.md](CMS_MEDIA_AND_PAGE_SETTINGS.md).
- Для локально опублікованого запису зберігаються попередні знімки; з адмінки їх можна повернути в чернетку для повторної перевірки й публікації. Це ще не історія віддалених Git-комітів чи деплоїв.
- Astro Content Collections читають опубліковані записи `pages`, `posts` і `projects`. Головна ALM бере свій запис через `getEntry('pages', ...)` та передає контент секціям; списки `/blog/`, `/portfolio/` використовують `getCollection()`.
- Є перший генератор маніфесту `cms/source-manifest.mjs`: без ALM-списку селекторів він знаходить секції та прості літеральні тексти/атрибути в Astro-шаблонах. `npm run cms:manifest` зараз виявляє 15 секцій і 142 прості поля головної. Маніфест коду поки що окремий інструмент аналізу; безпечний запис у `.astro` ще не підключено.
- `/admin` будує навігацію секцій і поля активної секції з реально відрендереної сторінки в прев'ю. Автоматично виявляються прості тексти, зображення, посилання й підказки полів; уже перенесені поля Content Collection беруть свої прив'язки з редакторського прев'ю. Панель має одну колонку з регульованою шириною 200 px–50%, окреме прев'ю, перемикання сторінок і бічні вкладки Admin/CMS/Media/Page settings. Вибір поля і елемента сайту синхронізовано.
- Редаговані тексти, посилання, зображення, меню та дані повторюваних блоків головної перенесено в один запис `pages`. Секції читають значення з нього; адмінка знаходить поля за стабільними `data-cms-path`. Колишні дві `staticText`-правки перенесено до полів запису. Перемикач «Кліки» зупиняє дії в прев'ю під час редагування.
- Додано вкладку Const для спільних значень статичного сайту. Прив’язка доступна через іконку всередині інпута справа; підключена іконка активна, а подвійний клік відкриває спільний редактор із кількістю використань. У прев’ю іконка з’являється на наведенні без постійних рамок. Телефонні та email-посилання мають формати `|tel` і `|mailto`. Підключення записів статей і портфоліо до Const лишається наступним етапом.
- Поля посилань підтримують URL/Page/Page section/Email/Phone та This tab/New tab. Автоматичні Page/Page section прив’язані до реєстру маршрутів і `id` секцій; метадані зберігаються в `content.linkSettings`. Горизонтальна навігація секцій слідує за скролом прев’ю.
- Локальні тести перевіряють збереження чернетки, валідацію, конфлікт ревізій, публікацію, завантаження медіа й видалення останнього запису з Astro Content Collections. `npm run build` проходить.

## Залишається до цільової CMS

- Визначити й реалізувати редактор форматованого довгого тексту, оптимізацію медіа під призначення, серверний alt і повний цикл віддаленої медіабібліотеки.
- Зробити захищене прев'ю чернеток візуально тотожним публічним Astro-сторінкам і придатним для інших типів сторінок.
- Реальний процес публікації через віддалений Git із атомарними змінами, статусом збірки, історією, відкатом та резервуванням медіа.
- Налаштування сайту й довільні сторінки, форми яких визначаються схемою конкретного проєкту.
- Реалізувати [кодову надбудову](CMS_CODE_FIRST_ARCHITECTURE.md) до кінця: стабільний зв'язок DOM-поля з вузлом Astro-маніфесту, безпечне точкове редагування літералів у коді, кодові декларації параметрів компонентів та виявлення конфліктів після правок розробника. Навігація й форми вже генеруються з прев'ю, але прив'язки раніше перенесених полів у `preview-fields.js` ще задані селекторами; це перехідний шар.
- Для головної сторінки редагований контент тепер рендериться Astro з полів запису. Перехідний механізм `staticText` зберігається для інших статичних маршрутів, які ще не переведені на [єдиний стандарт](CMS_CONTENT_STANDARD.md).
- Головна ALM та її SEO читають один запис `pages`. Старі дублікати `content.json` прибрано. Блоки головної, навігація й тексти форми перенесені в запис; візуальну перевірку цієї міграції виконує власник сайту.
- Версіоноване ядро й другий Astro-сайт для перевірки повторного використання.
- Повна перевірка доступності та всіх приймальних сценаріїв.

Поточна кнопка «Опублікувати локально» означає запис файлу в локальний проєкт. Вона не підтверджує деплой на хостингу. Новий API наразі доступний лише в локальному режимі; продакшен не слід перевести на нього до виконання решти пунктів.

**Пріоритет:** статичний ALM і його адмінка. Роботу над статтями та портфоліо відкладено до завершення локальної міграції та віддаленої публікації статичного контенту.

Прев’ю праворуч у `/admin` накладає чернетку на вибрану сторінку. Простий видимий текст можна змінювати подвійним кліком у прев’ю; SEO винесено в Page settings, а посилання й placeholder мають окремі поля секції. Текст, який створює JavaScript після завантаження, поки що не має стабільної прив'язки.

В ALM залишаються службові тексти поведінки (наприклад, повідомлення форми та підписи доступності) і послідовність кадрів анімації, яку формує код. Їхній контракт потрібно окремо визначити перед перенесенням до CMS.
