# Інструкція з налаштування та безпеки CMS для сайту ALM

Ця адмін-панель реалізована за сучасною архітектурою **Git-backed Jamstack / Serverless** (аналогічно до Yard Education):
- **Сайт залишається на 100% статичним і швидким** (віддається з Vercel Edge CDN).
- **Дані зберігаються у репозиторії GitHub** (`src/data/content.json`).
- **Кожна публікація — це Git Commit**: повна історія змін, неможливо щось втратити, доступний відкат до будь-якої версії.
- **Vercel Serverless Function** (`api/admin.js`) забезпечує бекенд-логіку: перевірку логіна/пароля, видачу захищених сесійних кукі та прямий комміт у GitHub.

---

## 1. Як працює вхід (Admin Login & Password)

1. Адмінка доступна за адресою:
   `https://ваш-домен.vercel.app/admin`
2. За замовчуванням у режимі локальної розробки діють параметри:
   - **Логін:** `admin`
   - **Пароль:** `alm2026`
3. Для продакшену ви задаєте власні логін і пароль у змінних середовища Vercel (див. розділ 2).

---

## 2. Змінні середовища у Vercel (Environment Variables)

Перейдіть у панель керування проектом на **Vercel** → **Settings** → **Environment Variables** та додайте такі змінні:

| Назва змінної | Опис | Приклад значення |
| :--- | :--- | :--- |
| `ADMIN_USER` | Логін адміністратора | `admin` (або ваш унікальний логін) |
| `ADMIN_PASSWORD` | Складний пароль адміністратора | Надійний пароль (наприклад: `ALM_Strong#Pass_2026!`) |
| `JWT_SECRET` | Довільний таємний ключ для підпису сесії | Випадковий рядок символів (32+ знаки) |
| `GITHUB_TOKEN` | Personal Access Token від GitHub з доступом до репозиторію | `ghp_xxxxxxxxxxxxxxxxxxxx` (з правами `repo`) |
| `GITHUB_REPO` | Назва вашого GitHub репозиторію | `nastyabanakh/ALM` |
| `GITHUB_BRANCH` | Робоча гілка для оновлення | `main` |

---

## 3. Як створити `GITHUB_TOKEN`

1. Увійдіть у свій GitHub акаунт.
2. Перейдіть у **Settings** → **Developer Settings** → **Personal Access Tokens** → **Tokens (classic)** (пряме посилання: https://github.com/settings/tokens).
3. Натисніть **Generate new token (classic)**.
4. Вкажіть назву (наприклад, `ALM-Vercel-CMS`) та термін дії (`No expiration` або бажаний період).
5. Поставте прапорець навпроти **`repo`** (Full control of private repositories).
6. Скопіюйте створений токен і вставте його у Vercel як `GITHUB_TOKEN`.

---

## 4. Рівень безпеки та найкращі практики

### Чому ця схема безпечна:
1. **HttpOnly & SameSite=Strict Cookie:** Токен сесії адміна записується у захищені кукі. JavaScript у браузері не має доступу до кукі (захист від XSS).
2. **Секрети на сервері:** `GITHUB_TOKEN` та `ADMIN_PASSWORD` зберігаються **виключно у Vercel Serverless Function** і ніколи не передаються в браузер.
3. **Відсутність SQL та класичної бази даних:** Уразливості на зразок SQL Injection тут фізично неможливі.
4. **Захист від Clickjacking:** Заголовки `X-Frame-Options: SAMEORIGIN` запобігають вбудовуванню адмінки на сторонні сайти.

### Додаткові рекомендації для максимального захисту:
- **Змініть дефолтний пароль:** Обов'язково вкажіть власний унікальний пароль у `ADMIN_PASSWORD` на Vercel.
- **Власний URL адмінки (опціонально):** Якщо ви хочете повністю приховати наявність адмінки від сторонніх ботів, папку `public/admin` можна перейменувати на приховану адресу (наприклад, `public/alm-secret-panel-777`).
